A practical bonus chapter

How to build an LLM

The models in this guide — Claude, ChatGPT — are closed: you can use them, but you can't hold them. A parallel world of open-weight models can be downloaded, inspected, and run on your own hardware. Here's how they're actually built, and how to run one yourself this afternoon.

first ·

What "open weights" means

A trained model is, in the end, just a very large pile of numbers — its weights, the values every dial in the network settled on during training (chapter 02). A closed model like GPT‑4 or Claude keeps that pile private: you send text to a company's servers and get text back, but the weights never leave their building.

An open-weight model publishes the pile. Anyone can download the file, run it on their own machine, fine-tune it, or study it — usually under a license that permits commercial use. It is not the same as fully open-source: the training data and code often stay private. What you get is the finished brain, free to run. That single difference is why a capable model can sit on your laptop with no internet connection and no bill.

The open ecosystem is now genuinely strong, led by a handful of families:

Qwen

Alibaba. A broad range of sizes, strong at coding and multilingual work; many releases use a mixture-of-experts design (ch 10a).

DeepSeek

DeepSeek AI. Large mixture-of-experts models known for strong reasoning at a fraction of the usual training cost.

Llama

Meta. The family that kick-started the open ecosystem and the format most tools support first.

Gemma

Google DeepMind. Small, efficient, high-quality models designed to run comfortably on a single GPU or laptop.

Mistral

Mistral AI. Compact European models with a reputation for punching well above their weight class.

Kimi

Moonshot AI. Very large mixture-of-experts models aimed at long-context and agentic use.

Nemotron

NVIDIA. Models tuned and released alongside the hardware and tooling they run on.
second ·

How an open model is built

Every one of those models — open or closed — is made the same way, on the same assembly line. It's a five-stage pipeline, and each stage is a chapter of this guide seen from the factory floor.

1
The data. Trillions of words of text and code, scraped from the web, books, and repositories, then aggressively filtered — deduplicated, stripped of junk and personal data, quality-scored. The old saying holds: a model is what it eats. Most of the gap between a good model and a mediocre one is decided here, before any training starts.
2
The tokenizer. Text is chopped into tokens — subword pieces (chapter 05). The team builds a fixed vocabulary (often ~100,000–200,000 pieces) by repeatedly merging the most common character pairs. This vocabulary is frozen for the life of the model.
3
The architecture. Almost always a transformer (chapter 06). The main design choices: how many layers deep, how wide, how long a context it can hold, and — increasingly — dense vs. mixture-of-experts (ch 10a), where only a slice of a huge network fires for any given token. This is why a "600-billion-parameter" model can be cheaper to run than the number suggests.
4
Pretraining. The expensive part. The network reads the entire dataset and does one thing, billions of times: guess the next token, check, adjust (chapter 08). This runs for weeks or months across thousands of GPUs and is where the money goes. The result is a "base model" — fluent, knowledgeable, but not yet helpful; it will happily continue your prompt instead of answering it.
5
Post-training. The polish that turns a text-continuer into an assistant. First instruction tuning — showing it thousands of examples of good answers. Then alignment — methods like DPO and RLHF (chapter 09) that teach it to prefer helpful, honest responses, and RLVR (chapter 18) that trains reasoning by rewarding correct final answers. Smaller models are often distilled from larger ones — taught to imitate a bigger sibling.

Then the weights are packaged and released — often with a technical report but rarely the data. The community takes it from there: fine-tuning it for niches, and quantizing it (more on that below) so it fits on ordinary hardware. That last step is what puts these models within your reach.

third ·

Running one yourself: the one number that matters

To run a model, your computer has to hold all those weights in fast memory at once. On a graphics card that's VRAM; on an Apple Silicon Mac it's unified memory shared between the chip and the graphics cores. This is the single constraint that decides what you can run. Everything else is detail.

The math is refreshingly simple. Each weight takes up a certain number of bytes depending on its precision. At full FP16 precision that's 2 bytes per weight, so a 7-billion-parameter model needs about 14 GB — more than most laptops have. The trick that changed everything is quantization: storing each weight in fewer bits. At 4-bit precision the same model shrinks to roughly 4 GB, with surprisingly little loss in quality. Quantization is the reason a 70-billion-parameter model can run on a gaming PC at all.

And Apple Silicon is a quiet star here: because its memory is unified, a Mac with 64 GB can run models that would need several graphics cards on a PC.

fourth ·

The stack: what actually runs the model

You don't wire up the transformer yourself — a small ecosystem of tools does it for you. Four are worth knowing, from easiest to most powerful:

Ollama

The simplest way in. One command downloads, quantizes, and runs a model, and manages them like Docker images. Cross-platform, and it exposes a local API. Start here.

LM Studio

A friendly desktop app with a chat window and a model browser — the same idea as Ollama, with a graphical interface instead of a terminal.

llama.cpp

The engine humming underneath most local tools. It's the C++ project that made models run fast on ordinary CPUs, consumer GPUs, and Apple's Metal — and it defined GGUF, the quantized file format everything uses.

vLLM

The production option. When you need to serve a model to many users at once, vLLM squeezes far more throughput out of a GPU. Overkill for a laptop; the right call for a service.
fifth ·

Do it: a running model in five minutes

Here is the whole path with Ollama, from nothing to a private model answering questions on your own machine. Match the model to what the calculator above said your hardware can hold.

# 1 · install (macOS/Linux — or download the app on Windows)
curl -fsSL https://ollama.com/install.sh | sh

# 2 · pull and run a model — this one is ~5 GB, fits 8 GB machines
ollama run qwen3:8b

# 3 · that's it. type and chat. it's running locally, offline.
>>> explain what a knowledge graph is, briefly

# 4 · optional: use it from your own code — OpenAI-compatible API
curl http://localhost:11434/v1/chat/completions -d '{
  "model": "qwen3:8b",
  "messages": [{"role":"user","content":"Hello"}]
}'

← Step 4 is the quiet superpower: any app written for the OpenAI API can point at localhost and run entirely on your own model, for free.

To browse what's available, ollama list shows what you've downloaded and ollama.com/library lists the rest. Pulling a bigger variant is just a bigger tag — qwen3:14b, gemma3:27b, deepseek-r1:32b — bounded only by the memory the calculator warned you about.

last ·

Which model should you run?

A rough map from hardware to a sensible starting point. When in doubt, pick a 4-bit build one size below your ceiling — the headroom keeps it responsive as the conversation grows.

8 GB — a modest laptop

Small models, 4-bit: Gemma 3 4B, Qwen3 4–8B, Llama 3 8B. Genuinely useful for writing, summarizing, and code help.

16 GB

Mid-size models shine: Qwen3 14B, Gemma 3 12B. A clear step up in reasoning and reliability.

24 GB — RTX 3090 / 4090

The sweet spot for enthusiasts: Qwen3 32B, DeepSeek-R1 32B, Gemma 3 27B, quantized. Approaching frontier quality on one card.

64–128 GB — Apple Silicon

Unified memory runs what PCs can't: 70B-class models comfortably, and smaller mixture-of-experts models whole. The best value in local AI right now.

And that closes the loop of this whole guide. The same ideas that make Claude and ChatGPT work — tokens, the transformer, the engine-room tricks, post-training — are sitting in a file you can download tonight and run on the machine in front of you. The frontier is closed; the foundation is open.
